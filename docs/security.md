# 安全边界与数据说明

FCP Cleaner 用于用户信任的本机文件环境。清理需要用户选择父文件夹、扫描、勾选候选和二次确认；启动或普通扫描不会自动清理。以下说明对应当前实现，不代表对所有文件系统、Final Cut Pro 版本或硬件的兼容性保证。

## 授权范围

[沙盒权限](<../FCP Cleaner/FCP Cleaner.entitlements>) 包含 App Sandbox、用户选择文件的读写访问和 app-scoped bookmarks。用户选择的是资源库所在父文件夹，应用只在这些已授权位置发现直接子资源库。授权一个父目录不会使其他磁盘位置自动成为清理候选。

Sparkle 2 自动更新使用出站网络权限及仅限本应用 `-spks` / `-spki` 的 Mach lookup 例外，启用 Installer XPC 服务。当前正式更新源为 `https://Xiong-mk.github.io/fcp-cleaner/appcast.xml`，配置有效时启动更新器。包内默认自动检查开启、自动下载关闭；Sparkle 保存的用户选择优先。自动检查、菜单「检查更新…」和用户允许的更新下载会联网；更新附件由 appcast 指向的 GitHub Releases HTTPS 地址提供。请求会向托管服务暴露正常网络连接信息，例如 IP 地址；源码未实现资源库路径、书签、扫描日志或清理日志的上传。

在应用「设置 → 软件更新」中可管理自动检查和自动下载；关闭自动检查后仍可手动检查。更新器拒绝非 HTTPS 或带账号密码的 feed URL。ZIP 更新包由应用内 `SUPublicEDKey` 对应的 Ed25519/EdDSA 公钥验证；私钥通过发布者钥匙串签名流程使用，不随源码或 App 分发。更新包签名与 macOS 代码签名分别验证，不能把 ad-hoc 签名视为 Developer ID 身份或 Apple 公证。设置与签名说明见 [Sparkle 集成](sparkle.md)。

[AuthorizedFolderStore](<../FCP Cleaner/FCP Cleaner/Services/AuthorizedFolderStore.swift>) 依赖书签解析和 `startAccessingSecurityScopedResource()` 成功才访问目录；保存的路径不是权限凭据。磁盘断开、书签失效或权限不足时显示错误并等待重试或重新授权。正常退出释放 scope；后台任务和当前清理操作在真正返回前继续持有独立 scope。

## 允许移动的内容

仅以下两类完整目录符合[路径白名单](<../FCP Cleaner/FCP Cleaner/Services/CleanupSafety.swift>)，其中 `L` 是已授权父目录的直接子 `.fcpbundle`，`E` 是库内一个直接子事件目录：

- `L/E/Render Files/High Quality Media`
- `L/E/Analysis Files`

高质量渲染目录包含匹配路径中的全部渲染；程序不能判定哪些“未使用”。移动后可能需要重新渲染或重新分析。原始媒体、代理/优化媒体、数据库、备份、包本体和外部存储位置不在白名单中；未检查的外部位置不能视为已确认安全。

程序拒绝路径穿越、错误层级或类别、符号链接、Finder 别名、非规范路径、跨设备候选树和身份信息不完整的候选。包根 `.fcpcache`、`.fcpdata` 仅作为保留管理入口记录并跳过，不读取或跟随。其他链接不因名称相似而获准。

## 变化检测与并发边界

扫描时捕获候选和祖先的设备号、inode、创建时间、mtime、ctime、逻辑大小、链接数及树内成员；预览和执行始终对照同一份原始快照。任何检测到的变化都要求重新扫描和确认。目录遍历及容量统计只读取元数据，不校验媒体内容的哈希。

最后一次路径复验和 `trashItem` 之间仍存在 TOCTOU（检查与使用间隔）窗口。当前实现没有基于文件描述符的原子移动保证，不能抵御恶意进程在该窗口内并发替换路径。使用时应保持资源库和磁盘稳定，结束会修改资源库的任务。

缩小这一窗口需要同时解决对象隔离、授权、失败恢复和崩溃恢复，不能靠再增加一次路径检查完成。分阶段方案及验收条件见 [清理竞态技术方案](cleanup-race-design.md)。

[运行中检查](<../FCP Cleaner/FCP Cleaner/Services/CleanupExecutor.swift>) 使用 `NSWorkspace` 辅助判断 Final Cut Pro 是否退出。它不能证明没有其他应用或后台任务占用文件，也不能锁定资源库；用户仍需在二次确认中声明编辑、渲染和导出任务已结束。

## 本机、外接磁盘和云盘

[卷检查](<../FCP Cleaner/FCP Cleaner/Services/CleanupVolumeChecker.swift>) 允许系统明确报告为“本地且非只读”的内置及外接磁盘。是否内置不影响资格；网络卷、只读卷、关键属性未知或读取失败会被拒绝。候选树本身仍必须位于同一设备。

外接盘需要保持连接，用户需通过原生面板授予目标文件夹访问权限，磁盘还需支持系统废纸篓操作。通过本地可写属性检查不等于保证废纸篓 API 一定成功。执行中断盘、权限变化或废纸篓失败会记录真实错误，不会改用永久删除。

云盘清理不受支持。实现拒绝路径组件中的 `Library/CloudStorage`、`Library/Mobile Documents`，并检查目标和祖先的 ubiquitous item 标记。这些检查不能完整识别所有第三方同步服务、自定义同步根目录或服务行为；即使某个同步目录通过检查，也不应将其用于清理。物理磁盘拔插、不同文件系统及具体设备应在专用虚拟库上另行验收。

## 废纸篓、取消与容量

实际移动只有 `FileManager.trashItem` 一个入口，不使用永久删除兜底，不自动清空废纸篓。系统废纸篓不等于备份；应用未提供自动回滚或恢复功能。需要恢复时先退出 Final Cut Pro，人工核对日志和系统废纸篓中的项目。

“停止后续项”不会撤回已完成移动，也不能中断正在执行的系统调用。正常退出会等待收尾；强制结束进程或崩溃可能留下 `pending`，它只表示结果未知，需要人工核对原位置和废纸篓，程序不会自动重试。

容量按文件系统分配容量统计，缺失时可使用文件大小；它是估算值。移入废纸篓通常还占用磁盘，且 APFS 克隆、硬链接、压缩、快照等会影响实际可回收空间。报告的“已移动估算占用”不能当作“已释放空间”。

## 本地数据与分享诊断

授权和日志位于应用沙盒的 Application Support 中，文件名和流程见[架构文档](architecture.md)。当前源码未实现遥测或日志上传。

- 授权文件包含 security-scoped bookmark 和真实路径，不应上传到公开仓库或问题附件。
- 扫描日志仅保留最近一次完成结果，包含授权目录、资源库、候选完整路径、容量及错误，不含媒体内容、书签数据或完整身份快照。
- 清理日志逐项保留原路径、状态、错误、估算容量和系统返回的废纸篓路径。日志写入失败会提示；最终状态无法落盘时停止后续清理。

公开反馈前，请遮盖用户名、卷名、项目名及路径中的敏感信息；不要提交真实资源库、媒体、书签或未脱敏日志。复现应使用新建的虚拟 `.fcpbundle`，保留失败条件和相关错误即可。测试通过不代表完成了真实工作库破坏测试或全部硬件验收。
